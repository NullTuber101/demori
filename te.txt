 Common Behavior

- JWT Interceptor adds tokens automatically  
- Role-based UI disables/hides actions dynamically  
- Backend @PreAuthorize ensures secure access control


 1.3 Security Architecture

1. Login → AuthController returns JWT Token
2. Interceptor → adds Authorization: Bearer <token> to headers
3. JwtAuthFilter → validates token & injects user context
4. SecurityConfig → sets route-level access based on roles
5. @PreAuthorize → enforces access inside controllers/services
6. Frontend → shows/hides buttons using role-check logic

---

 1.4 Cross-Origin/API Gateway Readiness

- @CrossOrigin(origins = "*") on backend controllers
- If deployed on cloud:
  - CORS needs fine-tuning for frontend domain
  - API Gateway (like Azure or NGINX) can route requests to backend securely
- Add Swagger UI for live API testing with token support

  2. Backend Low-Level Design

 Entity Relationship (ER) Mapping – DEMORI System

---

 Key Entities and Relationships

 1. User
- Fields: id, username, email, password, role
- Relationships:
  - Many-to-One with Role
  - One-to-One with UserRequest

---

 2. UserRequest
- Fields: id, fullName, email, brid, status, requestedRole
- Relationships:
  - One-to-One with User

---

 3. Role
- Fields: id, roleName, canApproveUsers, canWrite, canDelete
- Relationships:
  - One-to-Many with User

---

 4. Area
- Fields: id, name, leadName, leadEmail
- Relationships:
  - One-to-Many with Project

---

 5. Project
- Fields: id, projectName, status, areaId
- Relationships:
  - Many-to-One with Area
  - One-to-Many with Sprint

---

 6. Sprint
- Fields: id, sprintName, sprintStartDate, sprintEndDate, sprintJira, sprintDescription, project, status, assignedTo
- Relationships:
  - Many-to-One with Project
  - Many-to-One with Status

---

 7. Status
- Fields: id, statusName, progressPercent
- Relationships:
  - One-to-Many with Sprint

---

 8. ScrumArea
- Fields: id, name
- Relationships:
  - One-to-Many with Velocity

---

 9. Velocity
- Fields: id, scrumArea, sprint, velocityValue
- Relationships:
  - Many-to-One with ScrumArea
  - Many-to-One with Sprint

---

 Relationship Summary

text
User —— (1:1) —— UserRequest
User —— (M:1) —— Role

Area —— (1:M) —— Project
Project —— (1:M) —— Sprint
Sprint —— (M:1) —— Status

ScrumArea —— (1:M) —— Velocity
Velocity —— (M:1) —— Sprint


*All IDs are primary keys with auto-generation (IDENTITY strategy). Relationships managed using JPA annotations.*
